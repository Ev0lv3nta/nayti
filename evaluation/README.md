# Безопасная оценка поиска

Статус: corpus и инструменты подготовлены; **baseline и final model-backed прогон НЕ ВЫПОЛНЕНЫ**. Здесь нет достигнутых процентов качества или измеренной скорости телефона.

## Состав и ограничения

`corpus-v1.json` фиксирует 180 изображений и 116 запросов: 150 COCO val2017 фотографий с CC BY / CC BY-SA по snapshot метаданных и 30 собственных синтетических документов (10 семей по 3 варианта). Есть RU/EN visual, идентификаторы, буквальные фразы, опечатки, смысл документа, near-duplicates и отсутствующие идентификаторы. Holdout содержит 32 запроса; семейства документов/вариантов не пересекают разделы. Фото выбираются детерминированно по upstream object annotations, не по результатам Nayti.

Это начальный object/document benchmark, **не полный benchmark сцен и действий**. COCO object presence не доказывает все подписи к сценам. Отрицательные примеры проверяют несуществующие номера, а не универсальную способность visual-поиска отказаться от нерелевантной картинки. Для такой калибровки нужны дополнительные вручную проверенные scene/action/negative labels; её нельзя заменить порогом, выбранным на этих номерах. Одинаковые документные макеты могут быть трудными негативами для pHash — они намеренно не удалены.

Разделы development/holdout помещаются в разные MediaStore albums. Текстовые запросы проходят production bucket filter **до** отбора кандидатов. Поиск копий по текущему публичному контракту глобальный: там допускаются кандидаты обеих частей, положительные семейства не пересекаются. Не отбрасывать плохие результаты после поиска и не менять holdout после просмотра метрик.

## Происхождение и хранение

Изображения, модели и сырые прогоны остаются **вне Git**. Manifest содержит исходные COCO/Flickr ссылки, snapshot лицензии и SHA-256 каждого файла. Источник аннотаций: [COCO](https://cocodataset.org/#termsofuse), CC BY 4.0, COCO Consortium. Фотографии имеют отдельные лицензии исходных авторов, а не лицензию аннотаций. Перед перепубликацией фотографий нужно повторно проверить атрибуцию автора на исходной странице и действующие условия; этот каталог не является разрешением на их массовую публикацию. Для скриншотов продукта используйте только собственные synthetic documents, не внешние фото и не личную галерею.

Инструменты требуют Python 3.11+. `build_corpus.py` использует Pillow 12.3.0 и репозиторный Golos Text (его hash закреплён). Сначала скачайте `annotations_trainval2017.zip` по HTTPS-ссылке `ANNOTATIONS_URL` в скрипте. Хеш архива проверяется перед чтением.

```sh
python evaluation/build_corpus.py \
  --annotations ../evaluation/downloads/annotations_trainval2017.zip \
  --output ../evaluation/nayti-public-v1 \
  --font app/src/main/res/font/golos_text.ttf
```

Генератор не перезаписывает законченный корпус. Перед прогоном каждый файл и весь manifest сверяются с закреплённой версией. При несовпадении не «обновлять эталоны», а выяснить причину: версия Pillow, другой источник/байты или ошибка генерации.

## Android-путь

Тест `PublicCorpusEvaluationTest` по умолчанию пропущен, в release его и debug EntryPoint нет. При явном запуске он использует production Hilt graph: MediaStore → обычная каталогизация → signed pack import + реальные ARM64 KAT → foreground indexer → UnifiedSearch / PerceptualHashSearch. Нет подстановки готовых OCR/embeddings и fake encoders.

Нужна изолированная ARM64 Android-среда с пустой медиатекой либо ранее установленным **точно этим** корпусом. Установите актуальные debug и androidTest APK, предоставьте доступ к фото в тестовом профиле. Не используйте личную установку или личный профиль; приложение с release ID `app.nayti` не затрагивается. Runner ничего не устанавливает/удаляет, не сбрасывает данные и не меняет разрешения/пользователя. Android preflight откажется при любых посторонних media или catalog assets; существующие corpus-файлы сверяются по hash. Частично созданный fixture после сбоя требует осмотра, а не автоматического удаления.

Экспортируйте стандартные `JAVA_HOME`, `ANDROID_SDK_ROOT`, `NAYTI_ORT_AAR`. Runner пересобирает текущий чистый commit и сверяет хеши **обоих установленных APK**, чтобы не приписать старой сборке новый commit. Если они отличаются, установите получившиеся APK в тестовую среду и повторите с новым output-каталогом.

```sh
python3 evaluation/run_android.py \
  --adb "$ANDROID_SDK_ROOT/platform-tools/adb" --serial "$SERIAL" \
  --isolated-test-installation \
  --corpus ../evaluation/nayti-public-v1 \
  --pack ../model-lab/model-packs/nayti-offline-search-0.1.0-alpha.2.naytipack \
  --output ../evaluation/runs/baseline-01
```

Тест держит экран включённым только флагом окна Nayti и не меняет системный timeout. При resource pause он прекращается с причиной, а не отключает power/thermal policy. Верхняя граница — 15 минут на импорт и 45 на подготовку; это страховочные timeout, не обещание длительности. После прогона безопасный корпус остаётся для визуальной проверки. Сырые logs остаются в указанном локальном output, не в CI artifacts.

## Метрики и следующий gate

`score.py` требует полный реальный ARM64 прогон, все query IDs ровно один раз, правильный manifest hash, непротиворечивые ranks и только corpus IDs. Выводит counts Hit@1/Hit@5, MRR, размеры групп и p50/p95 (для маленьких групп интерпретировать осторожно). Отсутствующие номера: отдельно число выдач с production exact/literal reason и с любыми результатами. Scaled dot не интерпретируется как cosine или вероятность. Неполный/отменённый прогон не превращается в final report.

Сначала baseline на замороженном коде, затем разбор провалов и фиксация критериев **до** доработки на development. Потом final на неизменённом holdout, с APK/pack/commit и отдельной визуальной проверкой сложных сцен. Пока этого нет, не публиковать метрики и не заявлять закрытие quality gate. Отдельно нужны signed release smoke, стабильность/память, scrolling и accessibility на устройстве.
